# Ответы на контрольные вопросы

1. **Модульное тестирование** проверяет отдельный метод или класс изолированно. Интеграционное проверяет совместную работу модулей, системное — приложение целиком. Здесь проверяется калькулятор доставки без сети и базы данных.
2. **FIRST:** Fast — быстрые; Isolated — независимые; Repeatable — повторяемые; Self-validating — результат определяется автоматически; Timely — написаны своевременно. Это позволяет часто запускать тесты и доверять результатам.
3. **Белый ящик** использует знание исходного кода, условий и ветвей. **Чёрный ящик** проверяет входы и результаты по требованиям без анализа реализации. В работе использованы оба источника сценариев: бизнес-правила и структура условий.
4. **Code Coverage** показывает долю выполненного кода. Метрики: Statement, Line, Branch, Condition, Method, Path Coverage. Покрытие всех путей наиболее строгое: оно учитывает сочетания ветвей, а не только каждую ветвь отдельно.
5. **100% покрытия не доказывает отсутствие ошибок.** Например, тест может выполнить расчёт страховки, но проверить только положительный результат: ошибочный процент 3% вместо 2% тоже пройдёт. Поэтому проверяются конкретные ожидаемые суммы.
6. **xUnit:** `[Fact]` — один тест без параметров; `[Theory]` — тест с наборами данных; `[InlineData]` — данные рядом с тестом; `[MemberData]` — данные из метода или свойства; `[Trait]` — категория теста.
7. **Параметризованные тесты** подходят для одинаковой проверки с разными данными. В работе объединены расстояния около 10, 100, 1000 км, веса около 5, 20, 100 кг, типы доставки, страховые условия и значения около 50 000 руб.
8. **AAA:** Arrange создаёт калькулятор и заявку; Act вызывает `CalculateCost`; Assert сравнивает цену с ожидаемой или проверяет исключение. Секции явно подписаны в каждом тесте.
9. **TDD:** Red — сначала тест и подтверждённый провал; Green — минимальная реализация для его прохождения; Refactor — улучшение кода при зелёных тестах. В работе проведено четыре цикла и заключительный рефакторинг.
10. **FluentAssertions** даёт читаемые утверждения, понятные сообщения об ошибках и проверки объектов, коллекций и исключений. Примеры: `result.Should().Be(2040m)` и `act.Should().Throw<ArgumentException>()`.
11. **ReportGenerator:** зелёные строки выполнены; красные не выполнены; жёлтые имеют частично покрытые ветви. В промежуточном отчёте пропущены средние тарифы, часть типов и хрупкость; в финальном непокрытых строк нет.
12. **Инструменты:** xUnit выполняет тесты, Coverlet собирает покрытие, ReportGenerator создаёт HTML. Команды: `dotnet tool restore`; `dotnet test --collect:"XPlat Code Coverage" --settings coverage.runsettings`; `dotnet tool run reportgenerator "-reports:**/coverage.cobertura.xml" "-targetdir:coveragereport" "-reporttypes:Html"`.
13. **Границы варианта:** 0 и 5000 км; 0 и 1000 кг; тарифные пороги 10, 100, 1000 км; весовые пороги 5, 20, 100 кг; declared value 0 и 5000 руб.; итог 50 000 руб. Проверяются значения ниже, на границе и выше, чтобы обнаружить ошибки `<` и `<=`.
14. **Сложные ветви:** короткое замыкание `||` в валидации и `&&` в страховке, порядок коэффициента и надбавок, ограничение после всех расчётов. Покрыты отрицательным, нулевым и превышающим диапазон вводом, всеми комбинациями флагов, точными суммами 1600 и 2040 руб., а также суммами 49 999,99, 50 000 и 50 000,01 руб. до ограничения.
